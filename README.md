# RPG-битва

## 📖 Описание

Проект представляет собой пошаговую битву между двумя персонажами. Игрок выбирает класс героя (Воин, Маг или Лучник), вводит имя, после чего сражается с противником, которого тоже настраивает. Побеждает тот, кто первым снизит здоровье соперника до нуля

## Как запустить

1. Клонировать репозиторий:
```bash
git clone <url_репозитория>
```
2. Перейти в папку проекта:
```bash
cd lab_rpg_fio
```
3. Установить зависимости:
```bash
dart pub get
```
4. Запустить игру:
```bash
dart run
```

## Что изучили
* Наследование — создание классов-наследников (Warrior, Mage, Archer) на основе абстрактного Character с помощью extends

* Абстрактные классы и методы — Character нельзя создать напрямую, а метод attack() обязан быть реализован в каждом наследнике

* Переопределение методов — аннотация @override и вызов родительской реализации через super

## Ответы на вопросы
### 1. Что такое абстрактный класс? Почему нельзя написать Character() напрямую?
Абстрактный класс — это «шаблон», который описывает общую структуру и поведение для группы классов, но не предназначен для создания экземпляров. В нём могут быть как обычные методы с реализацией, так и абстрактные методы без тела
Character() нельзя создать, потому что в реальности не существует «просто персонажа» — существует конкретный воин, маг или лучник. Абстрактный класс задаёт контракт: любой наследник обязан реализовать методы без тела (например, attack() и toString())
### 2. Зачем нужен super в конструкторе наследника? Что будет если его убрать?
super(...) вызывает конструктор родительского класса
Если убрать вызов super, компилятор выдаст ошибку: у родительского класса нет конструктора без параметров, поэтому наследник обязан явно вызвать один из конструкторов родителя. Без этого поля name, hp и maxHp останутся неинициализированными, и объект нельзя будет корректно создать
### 3. В чём разница между @override у attack() в Warrior и takeDamage() в Warrior? Почему второй переопределяет метод который уже имеет реализацию в
родителе?
* attack() в родителе — абстрактный метод без тела. Warrior обязан его реализовать, иначе код не скомпилируется. @override здесь подтверждает, что мы реализуем контракт родителя

* takeDamage() в родителе — обычный метод с реализацией (уменьшает hp, не даёт уйти ниже нуля). Warrior переопределяет его, чтобы добавить свою логику: сначала уменьшить урон на величину брони, а затем вызвать super.takeDamage(reduced), чтобы воспользоваться базовой реализацией

Разница в том, что в первом случае мы обязаны дать реализацию, а во втором — можем изменить уже существующее поведение, при необходимости обратившись к родительской версии через super
### 4.Функция fight(Character a, Character b) не знает кто реально придёт — Warrior, Mage или Archer. Как называется эта концепция и где вы её уже видели во Flutter?
Это полиморфизм. Переменная типа родителя (Character) может хранить объект любого наследника, а вызов a.attack() динамически выбирает реализацию, соответствующую реальному типу объекта
### 5.Что означает _random с нижним подчёркиванием в классе Character?

Нижнее подчёркивание в Dart — это модификатор приватности на уровне библиотеки. Поле _random доступно только внутри файла character.dart, но не из других файлов проекта

Это пример инкапсуляции: генератор случайных чисел — внутренняя деталь реализации, и внешнему коду не нужно знать, как именно персонаж генерирует случайные значения. Если завтра мы захотим заменить Random на другой источник случайности, нам не придётся менять код снаружи
